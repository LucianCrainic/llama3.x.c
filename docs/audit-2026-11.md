Audit of `develop` at `29cc02e` (19 November 2026), the cleanup done on branch `refactor/simplify`, and the plan for what
remains. Guiding rule: complexity must justify its existence with a measured benefit, a correctness role, or a test role.

bitwise gates, no warnings under `-Wall -Wextra -Wpedantic`).

### F2. Two scheduler backends where one is the measured winner (done on this branch: OpenMP removed)

The engine schedules every kernel either on OpenMP (`LLAMA_BACKEND=omp`, the default until this branch) or on its own
worker teams. Teams
are faster (decode +4% to +11%, F2), are the only backend two sockets can use, and every campaign since F2 ran on them. The
OpenMP path costs 19 `#ifdef _OPENMP` blocks (`kernels_simd.c`, `report.c`), an `OPENMP` build switch, the `omp`/`teams` comparison axis in the tests, and
a surprising default: `make` builds without OpenMP (`OPENMP ?= 0`), so on one socket the default engine runs on one
thread on every platform. (Since F4, two sockets run on teams by default.)

Done on this branch, in two steps (owner's decisions of 20 November 2026):

1. Teams became the default backend on one socket too (`7384ee9`). Validation: section 6, one-socket A/B against OpenMP
   on one node: decode 5-8% faster on teams (8B Q8_0 a tie), prefill within 2% except 1B FP32 (6.5% slower).
2. The OpenMP backend was removed: the `#ifdef _OPENMP` blocks, the `OPENMP` build switch (`make OPENMP=1` now stops with
   the reason), the `omp` rule in the socket choice, the report's `openmp*` build fields, and the backend axis of the
   tests. Without a team (the unit tests) kernels run serially, as the default build always did. `LLAMA_BACKEND=teams`
   is still accepted so the campaign scripts need no change; any other value fails at load like a retired knob.
   Scripts: the campaign library no longer pins `omp`, `backend_env` knows only teams, and the configurations that
   measured OpenMP itself are gone (the F2 model comparison, the omp side of the A4 and C1 bitwise gates, the A6
   `omp-file` baseline); the B7 control (OpenMP, 112 threads, one process over both sockets) is now one team of 112
   threads. `cresco8-kernels.sbatch` and `cresco8-profile.sbatch` run the tree under test on teams of the same thread
   counts (the K campaign's `BASE_ROOT` is an older tree and keeps its own OpenMP build; the profile's OpenMP fork/join
   probe is replaced by the team barrier benchmark). Rerunning an old campaign therefore measures teams where it once
   measured OpenMP.

### F3. The forward pass exists six times

`run.c` and `runq.c` each have a per-token layer, a batched layer, the batch driver, the run-state allocator, packing and
the engine adapters; 425 of their lines differ only by precision. `tp.c` has a third copy of each (FP32 decode, Q8 decode,
batched) that already generalizes the other two: its shard planner supports one socket (`shards.h`: "S = 1 is the same
code"). Engine-level decisions are duplicated too (the Q8 prefill kernel choice is written twice in `runq.c`).

Recommendation, in two steps:

1. Merge `run.c` and `runq.c` into one engine with a small precision interface (embed row, project, quantize), keeping
   two executables or selecting by checkpoint header. Risk: medium; gates are bitwise for every path on the scalar kernels.
   **Done on this branch:** `src/engine.c` (751 lines) replaces the two engines (1,137 lines); `run.c` and `runq.c`
   only set `engine_q8`, so the CLI, the reports and every test are unchanged. The precision is confined to the embedding
   row, four per-token projection helpers (`project_qkv`, `project_add`, `project_swiglu`, `project_classifier`), one
   batched helper (`project_rows`: FP32 GEMM, BF16 GEMM on packed weights, or quantize + Q8 GEMM) and the packing; each
   keeps the former kernel calls, order and profile phases. The Q8 prefill-kernel choice is written once (the two-socket
   branch now also logs the W8A32 and portable-fallback notes). One intended difference: per-token Q8 decode now writes
   K/V straight into the cache rows as FP32 did, instead of a staging row plus `memcpy`, so with `LLAMA_KV_LAYOUT=rows`
   Q8 profiles no longer show a `kv_store` phase. Validation: old (62c487e) against new probes, bitwise on all 576
   comparable runs: FP32, Q8 W8A8/W8A32, BF16 (AMX and reference), AMX-INT8; scalar, emulated AVX-512 and emulated AMX;
   1 and 2 sockets; tiled/split prefill, split/group decode; both K/V layouts; batch default/1/5; group sizes 4 and 64.
2. Run one socket through the shard engine with S = 1, so there is one forward per mode (decode, batched) instead of three.
   Risk: high: the one-socket path would then always own its weights (today `file` mode maps them) and gains the
   coordinator indirection. Validation: D2-style A/B on one node for 1B/8B, FP32/Q8, decode and prefill, before merging.

### F4. Defaults lag the decisions (done on this branch, owner's decision of 20 November 2026)

D2 recommended batched prefill by default, AMX-INT8 by default for Q8 when AMX exists, and two sockets by default on a
dual-socket HBM node ([numa-tp-prefill-results.md](numa-tp-prefill-results.md) §7), but the code defaults were unchanged,
so a run with no knobs took the slowest path measured (per-token prefill, one socket). Done: the rules of
[architecture.md](architecture.md) §2.1. Each applies only while its knob is unset; two sockets imply teams and, on an HBM
node, HBM placement (what D2 measured; `file` would leave the shards in DDR by first touch); the batch default applies only
where the batched GEMM runs, so scalar builds stay per token. Under `LLAMA_KERNELS=auto`, AMX is taken for W8A8 batched
prefill and for the explicit BF16 mode (which now runs with no other knob on AVX-512); the tile permission is requested
only then, so a plain FP32 run still reports it "not requested" (C4). The campaign library pins the old defaults job-wide, as it
already did for `LLAMA_ATTN`, so the recorded phases rerun unchanged. Tests: `test_numa.py` `DefaultTests` (fake Flat,
Cache, one-socket and no-numaperf nodes, and every knob that keeps one socket), `test_tp.py` (two sockets imply teams).

Found on the way and fixed: the report's `runtime.placement` read `file` for every two-socket run, whatever the shards'
placement (only the one-socket loader set it).

### F5. Knob sprawl (done on this branch)

After F1 the engine read 31 knobs. Sweep-only knobs whose sweeps are finished were removed, keeping their defaults, and
added to the retired-knob guard: `LLAMA_GEMV_SCHED` (with the dynamic split and the Q8 claiming path, which only the
knob could reach), `LLAMA_ATTN_ROW_BLOCK`, `LLAMA_ATTN_TILED_QUERIES`, `LLAMA_ATTN_TILED_ORDER` (with the longest-first
ordering), `LLAMA_ATTN_WORKSPACE_MIB`, `LLAMA_GEMM_KC`, and the `LLAMA_ATTN=amx` placeholder of the postponed E3. The
report's `runtime.attn_row_block` field went with its knob. Kept, as documented test-only knobs:
`LLAMA_LOADER_CHUNK` and `LLAMA_LOADER_MAX_READ`, the only way the end-to-end tests reach the loader's multi-chunk and
short-read paths on small fixtures.

Coverage the knobs gave is kept through C test hooks: `k_gemv_force_hybrid` runs the FP32 GEMV, partial and row-parallel
tests on the hybrid split (which the engine uses only from 96 MiB up), and `k_attention_set_workspace_mib` replaces the
environment variable in the multi-wave attention tests. The row-block test became a waves test (one-wave against
two-row waves, bitwise).

Validation: `make test` locally; 80 probe comparisons against `62c487e` (FP32 and Q8_0, scalar and emulated AVX-512,
one and two sockets, per-token and batched prefill, tiled and split prefill, split and group decode, both K/V layouts)
are bitwise equal. The E0 and E2 sweep cells of `cresco8-prefill.sbatch` now fail at load; rerun them from a commit
before F5.

### F6. Campaign infrastructure outweighs the engine (done on this branch)

Scripts, campaign tools and their tests are about 9,500 lines, close to the engine's size. Most of it drives finished
phases (A1-A6, B1-B7, C1-C7, D1-D3, E0-E4) or summarizes one campaign (`summarize_e2.py`, `summarize_e4.py`, `e6_model.py`,
`summarize_attention_bench.py`, ...). The results documents already cite the commit of every campaign, so these phases are
reproducible from history and do not need to live at `HEAD`.

Recommendation: tag the current tree (`campaigns-2026-11`), then keep at `HEAD` only a generic `check` stage (build, test,
gates against the reference) and a generic `bench` matrix (model x precision x sockets x prompt x context), one summarizer
(`summarize_campaign.py` + `campaign_tables.py`) and the validation tools (`validate.py`, `compare_engines.py`,
`compare_generation.py`, `check_placement.py`). Risk: low for the engine, medium for ongoing cluster work; do it after the
E5 branch lands.

**Done.** Tag `campaigns-2026-11` (at `a8f3902`) keeps the six phase scripts and the one-campaign summarizers
(`summarize_e2.py`, `summarize_e4.py`, `e6_model.py`, `summarize_attention_bench.py`, `summarize_gemm.py`,
`summarize_profile.py`, `summarize_kernels.py`, `summarize_generation.py`). `HEAD` keeps one job, `scripts/cresco8.sbatch`:
`STAGE=check` (build, `make test`, and per model the one-against-two-socket gates, the defaults and the BF16 prefill
against the one-socket per-token reference, the Hugging Face gate and placement-checked smoke runs) and `STAGE=bench`
(model x checkpoint x sockets x prompt x retained context, interleaved repeats, a profiled run per cell). Both run at the
engine defaults; the library no longer pins the pre-F4 defaults job-wide, and `PHASE` is refused with a pointer to the tag.
Kept tools: `summarize_campaign.py` + `campaign_tables.py`, `validate.py`, `compare_engines.py`, `compare_generation.py`,
`check_placement.py`, `make_prompts.py` (and the exporter). Scripts, campaign tools and `test_tools.py` went from about
7,800 lines to 2,540. `test_tools.py` now checks the two stages' dry-run matrices and knob validation; the tests of the kept
tools and of the C benchmarks are unchanged.

### F8. Smaller items

- **Unused sizing model (done on this branch).** `tp_choose_batch`, `tp_exchange_fraction`, `tp_peer_bytes_per_token` and
  `tp_exchange_payload_bytes` modelled microbatch sizes (D1 §4.2), but nothing in the engine called them; the batch size is
  chosen by the measured sweep. Removed with their tests; `tests/sizing.c` keeps the region-size checks that `tp_create`
  depends on (`tp_work_bytes`, `tp_exchange_bytes`).
- **Test hooks in public headers (done on this branch).** The hooks only tests and benches call (portable references,
  `k_gemm_*_test`, `k_attention_batch_portable*`, `k_attention_set_task_hook`, `k_gemv_force_hybrid`,
  `k_attention_set_workspace_mib`, the kernel-selection overrides) moved from `kernels.h` / `gemm.h` to
  `include/testing.h`. `ReduceStamps` stays in `workers.h`: `tp.c` fills it in production for the exchange profile.
- **`kernels_simd.c` split (done on this branch).** The 2,500-line file is now `kernels_simd.c` (ISA selection, team
  setters, row segments, norm/RoPE), `gemv.c` (GEMV/Q8 drivers and kernels, static/hybrid scheduling, quantization) and
  `attention.c` (attention kernels, dispatch, K/V layout), sharing `src/kernels_internal.h`. Move only: no function body
  changed; the separate `sched.c` was not worth it once F5 left two schedules.
- **`tp.c` profile** keeps its own copy of the phase names (`log_profile`). Its slots extend the engine's phases with
  `wo_mm`/`w2_mm` and the exchange split, so sharing `profile_phase_name` needs the slot enum to be built on `Phase`
  first. Cosmetic; left as is.
